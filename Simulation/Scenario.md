\# Phishing Simulation Scenario



\## 1. Scenario Objective



The objective is to safely demonstrate how an attacker could use IT-support impersonation and a fraudulent login page to influence a user into interacting with a phishing message.



The scenario is based on the social-engineering and credential-phishing techniques documented in the Twitter 2020 incident.



\---



\## 2. Scenario



A simulated internal IT/security notification informs a designated test user that their corporate VPN access requires verification.



The message directs the test user to a controlled laboratory landing page.



The landing page is designed only for the simulation and does not collect real credentials.



\---



\## 3. Social Engineering Elements



The scenario will demonstrate common phishing indicators such as:



\- Impersonation of an internal IT/security function.

\- Urgency or account-security messaging.

\- A request to verify access.

\- A login-style landing page.

\- A simulated credential submission.



\---



\## 4. Test Environment



The simulation will use:



\- Authorized test accounts.

\- Dummy usernames and passwords.

\- Controlled laboratory systems.

\- A safe landing page.

\- No real organizational credentials.



\---



\## 5. Expected User Behaviors



The simulation will measure whether test users:



1\. Open the message.

2\. Interact with the link.

3\. Recognize suspicious characteristics.

4\. Submit dummy information.

5\. Report the simulated phishing message.



\---



\## 6. Metrics



The simulation will attempt to measure:



\- Emails delivered.

\- Emails opened, if supported.

\- Link clicks.

\- Dummy credential submissions.

\- Phishing reports.

\- Time to report, if measurable.



No metric will be recorded unless the platform actually provides the required data.



\---



\## 7. Safety Controls



The simulation will not:



\- Target real employees without authorization.

\- Collect real passwords.

\- Collect personal information.

\- Target external organizations.

\- Use real corporate login pages.

\- Attempt unauthorized access.



All interactions will remain within the controlled laboratory environment.



\---



\## 8. Training Objective



The simulation is intended to demonstrate how social engineering can exploit employee trust and why users should verify unexpected IT/security requests before providing information.



The results will later be used to develop security-awareness recommendations.
