\# Phishing Simulation Lab Environment



\## 1. Objective



The objective of the laboratory environment is to safely demonstrate phishing behavior using test accounts and dummy information.



The environment will not target real employees, organizations, or external systems.



\---



\## 2. Lab Components



| Component | Purpose |

|---|---|

| Windows Host | Main workstation |

| Kali Linux VM | Security testing environment |

| GoPhish | Phishing simulation and campaign tracking |

| Test Email Account | Receives controlled simulation emails |

| Test Browser | Interacts with the safe landing page |

| Dummy Credentials | Used only for simulation |

| GitHub Repository | Documentation and evidence |



\---



\## 3. Isolation



The simulation will be conducted in an authorized laboratory environment.



The following restrictions apply:



\- No real employee accounts will be targeted.

\- No real passwords will be collected.

\- No personal or sensitive information will be used.

\- No unauthorized external organization will be targeted.

\- Only designated test accounts will participate.

\- Dummy credentials will be used for any simulated submission.

\---



\## 6. Security and Ethical Controls



The simulation will remain strictly controlled.



Real credentials, personal data, API keys, passwords, or sensitive information must never be stored in the project repository.



The purpose of the simulation is security awareness and research, not unauthorized credential collection.



\---



\## 7. Validation



Before conducting the actual simulation, the environment will be tested to confirm:



1\. GoPhish is functioning.

2\. Test email delivery works.

3\. The safe landing page is accessible.

4\. Dummy interactions are recorded correctly.

5\. Campaign metrics are available.



Only after successful validation will the baseline simulation be conducted.
